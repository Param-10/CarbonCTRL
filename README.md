# CarbonCTRL

CarbonCTRL helps US businesses measure their carbon footprint, see how it compares with similar businesses, and cut it. You log your monthly bills and activities, and the app turns them into emissions, a grade, AI recommendations and a report.

## Features

- Sign up with email or Google. Reset a forgotten password by email.
- Guided first-run setup: company details, a quick footprint from your bills, then your first results.
- Log activities one at a time or a whole month at once, in US units (kWh, therms, gallons, miles, lbs). Edit or delete them, with undo.
- Dashboard with total emissions, a grade from A+ to F, a breakdown by category, a monthly trend and progress toward your target.
- AI recommendations from Google Gemini that fit your budget, premises and vehicles. They refresh on their own when your data changes.
- Action plan: add recommendations, mark them done, and track progress toward your reduction target.
- Emissions report for any period, as a CSV download or a printable page.
- Methodology page listing every emission factor and its source.
- "How it works" guide for new users.
- Optional monthly reminder email to log last month.

## Tech stack

- **Frontend:** React 18, TypeScript, Vite, Tailwind CSS, Zustand (state), Recharts (charts), Framer Motion (animation)
- **Backend:** Node.js 24, Express, SQLite with Drizzle ORM
- **AI:** Google Gemini (`@google/genai`)
- **Email:** Resend (password reset and reminders)
- **Tests:** Vitest and Supertest

## Repository structure

```text
src/                  React app
├── pages/            One file per screen (Dashboard, Recommendations, Report, ...)
├── components/       Shared UI: layout, charts, dialogs, route guard
├── store/            Zustand stores that load and cache data from the API
├── lib/              API client, option lists, formatting helpers
└── hooks/            Small React hooks (dialog keyboard handling, page memory)

server/               Express API
├── index.js          Entry point: loads env, opens the database, starts the server
├── app.js            Middleware (CORS, rate limits) and route mounting
├── routes/           HTTP endpoints, grouped by feature
├── services/         Business logic: scoring, Gemini calls, reports, reminders
├── config/           Emission factors, state grid rates, industry benchmarks, profile options
├── db/               Schema, data access (repos.js), migrations and drizzle.config.js
├── scripts/          checkRecommendations.js: live test of the Gemini setup
├── tests/            API and logic tests
└── vitest.config.js  Test settings
```

- `server/config/` holds the numbers. Each emission factor names its source (mostly the US EPA).
- `server/db/migrations/` is generated by Drizzle. After changing `server/db/schema.js`, run `npm run db:generate`. Migrations run automatically when the API starts.
- The root only holds what the tools expect there: `package.json`, `index.html`, `vite.config.ts`, `tailwind.config.js`, `tsconfig.json` and `eslint.config.js`.

## How the application works

1. The React app calls the Express API (`/api/...`) with a JWT in the `Authorization` header.
2. The API stores companies, activities, saved recommendations and action plans in a local SQLite file.
3. Each time it is asked, the API calculates the score from the stored activities: amount × emission factor. Grid electricity uses the company's state rate.
4. The grade compares yearly emissions per employee with a typical business in the same industry and state.
5. For recommendations, the API sends the company profile and emissions to Gemini, checks the reply against the profile, and saves the result.
6. When data changes, the API regenerates the saved recommendations in the background (at most once every 10 minutes per company).

## Setup

You need Node.js 24 (see `.nvmrc`).

```bash
git clone https://github.com/Param-10/CarbonCTRL.git
cd CarbonCTRL
nvm use
npm install
```

Create `server/.env`:

```bash
JWT_SECRET=any-long-random-string
PORT=5000
FRONTEND_URL=http://localhost:5173
GEMINI_API_KEY=your-gemini-key     # optional, see below
GOOGLE_CLIENT_ID=your-client-id    # optional, for Google sign-in
```

Create `.env.local` in the project root:

```bash
VITE_API_URL=http://localhost:5000/api
VITE_GOOGLE_CLIENT_ID=your-client-id   # same as GOOGLE_CLIENT_ID
```

Always set `VITE_API_URL`. Without it, the app uses the production API.

Run the API and the frontend in two terminals:

```bash
npm run server   # API on http://localhost:5000
npm run dev      # app on http://localhost:5173
```

The database file is created at `server/data/carbonctrl.db` on first start.

## Environment variables

**Server (`server/.env`)**

| Variable | Required | Purpose |
| --- | --- | --- |
| `JWT_SECRET` | Yes | Signs session tokens. The server will not start without it. |
| `PORT` | No | API port. Default `5000`. |
| `FRONTEND_URL` | Yes in production | Allowed browser origin(s), comma-separated. The first one is used for links in emails. |
| `GEMINI_API_KEY` | No | Turns on AI recommendations. Without it, standard recommendations are shown with a notice. |
| `GEMINI_MODEL` | No | Main model. Default `gemini-pro-latest`. Pro models need billing enabled on the key's Google Cloud project. |
| `GEMINI_FALLBACK_MODELS` | No | Comma-separated models to try when the main one is out of quota or busy. |
| `GOOGLE_CLIENT_ID` | No | Turns on Google sign-in. |
| `GOOGLE_CLIENT_SECRET` | No | Only needed for the older Google popup sign-in flow. |
| `RESEND_API_KEY` | No | Sends password reset and reminder emails. |
| `RESET_FROM_EMAIL` | With Resend | Sender address on a domain verified with Resend. |
| `REMINDER_FROM_EMAIL` | No | Different sender for reminders. Defaults to `RESET_FROM_EMAIL`. |
| `DATABASE_PATH` | No | Use a different SQLite file. |
| `TRUST_PROXY` | No | Number of proxies in front of the API (e.g. on Render), so rate limits see the real client IP. |

**Frontend (`.env.local`)**

| Variable | Purpose |
| --- | --- |
| `VITE_API_URL` | API base URL, e.g. `http://localhost:5000/api` |
| `VITE_GOOGLE_CLIENT_ID` | Google sign-in client ID (same as the server's) |

## Main features and flows

- **Onboarding.** New users without a company profile are sent to `/onboarding`. It saves the profile, logs last month from bill amounts, and shows the first grade and top actions.
- **Activities.** Each activity has a category, type, amount and date. "Log a month" replaces that month's total for each type, so saving twice never counts twice.
- **Score and grade.** Calculated on every request from the stored activities, so changes to factors apply to old data too. Office-type businesses are graded on building energy (electricity and heating). Industrial businesses are graded on total emissions. Grades are marked provisional until three months are logged.
- **Recommendations.** Gemini returns 4-6 actions as structured JSON. The API drops actions that don't fit the profile (for example, rooftop solar for a tenant), caps each impact at the category's emissions, and retries once if too few remain. If Gemini is unavailable, the API returns standard recommendations and explains why.
- **Action plan.** Actions are stored with a yearly saving. Progress compares done and planned savings with what the reduction target needs.
- **Report.** Lists every activity in a period with its factor and emissions. Download it as CSV or print it.
- **Reminders.** If turned on in Settings and email is set up, the API emails users who haven't logged last month, from the 5th of each month.
- **Limits.** The API allows 1,000 requests per 15 minutes per IP, with stricter limits on sign-in, password reset and AI generation.

## Notes

- Emission figures are estimates for managing emissions, not an audited inventory. Some factors are marked "indicative" on the Methodology page.
- `/offset-projects` is an unfinished prototype that shows sample data. It is not in the menu.
